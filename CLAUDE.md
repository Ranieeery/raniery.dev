# CLAUDE.md

Guidance for Claude Code when working in this repository. See `README.md` for
the project overview, structure and how each feature works.

## Commands

```bash
npm run dev            # dev server, http://localhost:3000
npm run build          # production build (also generates route types)
npm run start          # serve the production build
npm run lint           # ESLint
npm run format         # Prettier write
npm run format:check   # Prettier check
```

There is no test suite. Verify changes with build, lint, format check, and by
loading the production build in a browser.

## Git

- Do not commit, push or create branches. Leave changes in the working tree;
  the owner reviews and commits.
- When asked for a commit message, use Conventional Commits (`feat`, `fix`,
  `refactor`, `docs`, `chore`, `style`). Mark breaking changes with `!` and a
  `BREAKING CHANGE:` footer. The version in `package.json` follows SemVer.

## Architecture rules

- **Next.js 16 App Router, fully static.** Docs for the installed version are
  in `node_modules/next/dist/docs/`; check them before using an API you're not
  sure about. `PageProps`/`LayoutProps` are global types generated by
  `next build` / `next dev`.
- **Two root layouts:** `app/[lang]/layout.tsx` for the site and
  `app/(root)/layout.tsx` for the `/` redirect page. There is no
  `app/layout.tsx`, and there should not be one.
- **Server components by default.** Use `"use client"` only for components
  that need the browser (theme, language switcher, menus, scroll spy, reveal
  observer). Hooks and helpers don't get the directive.
- **Prefer `useSyncExternalStore`** to `setState` inside `useEffect` when
  reading browser state (theme, scroll position). The React lint rules flag
  synchronous `setState` in effects.

## Content and i18n

- **Source of truth:** the CVs in `public/cv/`. If the site conflicts with a CV,
  the CV wins.
- **No duplicated content between languages.** Language-independent data goes
  in `src/content/profile.ts`. Translatable text goes in
  `src/i18n/dictionaries/{pt,en}.ts`, typed by `src/i18n/types.ts`. Strings
  shared by several sections go in `common`.
- **No hard-coded user-facing text** in components. That includes `aria-label`s
  and screen-reader text, which also come from the dictionaries. Brand and
  proper names (GitHub, LinkedIn, project names) live in `profile.ts`.
- **Locales:** `pt` (default, `pt-BR`) and `en`. Route segments are `/pt` and
  `/en`.
- **Wording rules:**
  - Never show the phone number anywhere on the site. Contact is email,
    LinkedIn and GitHub only.
  - English uses "Resume" (no accents). Portuguese uses "currículo".
  - Write "Go", not "Golang".
  - English uses "Backend"/"Frontend"; Portuguese uses "Back-end"/"Front-end".
  - Company names and job titles stay exactly as each CV has them. "Empresa 1"
    is a real company name. English uses "Engineering", Portuguese uses
    "Engineering do Brasil".

## Design rules

- **Palette:** hue 245, defined as tokens in `globals.css`. Use the Tailwind
  token classes (`bg-bg`, `text-fg`, `text-muted`, `text-subtle`,
  `text-accent-text`, `border-line`, …), never raw colors. Places that can't
  read CSS variables use `src/lib/theme-colors.ts`; keep it in sync with
  `globals.css`.
- **Text vs. fill accent:** use `text-accent-text` for accent-colored text; the
  plain `accent` is for fills and lines. That keeps AA contrast in both themes.
- **Strong typography and spacing over decoration.** Editorial layout: numbered
  section label on the left, content on the right.
- **Avoid generic AI-generated aesthetics:**
  - no gradient blobs, glassmorphism, glow or neon
  - no typewriter text or "Hi, I'm X" hero
  - no emoji as icons or bullets
  - no cookie-cutter card grids
- **One code-themed accent only:** the `<Raniery>` / `</Raniery>` text logo
  (`components/ui/Logo.tsx`). Don't add other code-style decorations.
- **Motion:**
  - subtle (fade or slide of about 12px, refined hover states)
  - always disabled under `prefers-reduced-motion`
  - content must stay visible without JavaScript
- **Icons:** inline SVGs in `components/ui/Icon.tsx`. No icon fonts or CDNs.

## Accessibility and SEO

- **Contrast:** WCAG AA in both themes.
- **Focus:** visible focus styles, plus a skip link to `#main`.
- **Touch targets:** at least 44px.
- **Icon-only controls:** need an accessible name, and decorative icons get
  `aria-hidden`.
- **Semantics:** semantic landmarks and exactly one `h1`.
- **External links:** use `ExternalLink` (new tab, `rel`, screen-reader hint).
- **Metadata:** per-locale metadata, canonical, `hreflang` alternates,
  Open Graph/Twitter, sitemap and robots. New pages must go through
  `buildMetadata` in `src/lib/seo.ts`.

## Code conventions

- **File names:** components are `PascalCase.tsx`; every other module
  (helpers, hooks, config) is `kebab-case.ts`.
- **Types:** strict TypeScript, no `any`. Derive id types from the data in
  `profile.ts`.
- **Sections:** read their copy as `const t = dict.<section>` and receive
  `dict`, plus `locale` when needed, as props.
- **No dead code:** no unused exports, props or icons.
- **Formatting:** Prettier (`.prettierrc`), 2-space indentation, LF line
  endings.

## Definition of done

1. `npm run build` passes with no errors or warnings.
2. `npm run lint` and `npm run format:check` pass.
3. Lighthouse ≥ 90 in all categories for `/pt` and `/en`, on mobile and
   desktop, against `npm run start`. Locally, Best Practices loses a few points
   to the Speed Insights script, which only loads on Vercel.
4. No accessibility violations in light and dark themes, at mobile and desktop
   widths.

## Gotchas

- **Stale server on Windows:** when restarting `next start`, make sure the old
  process released the port. A stale server serves old assets for new HTML and
  breaks the page.
- **Hydration warnings:** the theme script sets `data-theme` before hydration,
  so `<html>` uses `suppressHydrationWarning`. Don't remove it.
